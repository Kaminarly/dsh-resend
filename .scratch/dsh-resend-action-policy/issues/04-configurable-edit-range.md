## 验收条件

- [x] 新增并持久保存「只允许编辑重发最后一条用户消息」，默认开启，与重新生成范围及显示方式独立。
- [x] 该设置常驻显示 spec 原文：「关闭后可编辑重发较早消息。操作将从该消息重新续接，并发送修改后的内容，其后的对话将退出当前上下文，原始记录仍保留。」开启和关闭时说明均可见。
- [x] 范围开启时，较早消息的编辑图标保留并置灰，下方准确提示「只能编辑重发最后一条用户消息」；范围关闭后允许较早有效用户消息。
- [x] 内联编辑入口、关闭内联编辑时的 Composer 入口、已打开编辑框的发送与 Composer 按钮、Enter 及等价操作路径均受限制，旧回调不能绕过。
- [x] 只把真实用户发送的有效消息计入最后一条；排除被替换记录、Carrier 和宿主注入。最新无文字用户消息仍参与最后一条判定，不把编辑资格转给前一条有文字消息。
- [x] 开启限制或新增用户消息使已打开编辑框失去资格时，保留修改内容，允许继续修改、复制和取消，禁用发送与放入 Composer；恢复资格后不丢草稿并可继续操作。
- [x] 普通复制、手动输入及 Composer 新消息不受限制；已经通过允许入口放入 Composer 的普通草稿不因后来开启限制而被清空或拦截。
- [x] 实际请求处理按已保存范围核验，新增 not-last-user-message，并统一错误集合、严格结果描述、中文及英文提示和检查；锁内与写入前重查，拒绝不产生部分回退。
- [x] 正在生成、目标已失效、空文字和 Composer 忙碌等原有保护继续生效；合法既有补发不受新范围误伤。
- [x] 操作较早用户消息继续使用 Replay turn，发送修改后的准确文字，后续内容退出模型上下文、原始日志保留，不弹确认框。
- [x] 用真实宿主组装器验证历史窗口、实时新增及回退；运行鼠标、键盘、直接请求和编辑资格变化的代表性场景，保存设置不丢失草稿。

## Answer

已完成编辑范围开关的保存、读取和操作限制。最后一条用户消息由宿主完整有效对话确定，所有编辑入口与实际请求均遵守已保存范围；编辑框失去资格时保留草稿，恢复后可继续。普通复制和 Composer 新消息不增加限制，放入 Composer 的普通草稿不会因后续设置变化被清空。

较早消息仍使用 Replay turn，准确发送修改文字，后续内容退出有效上下文，原始日志保留。新编辑记录核验补发的原目标与准确文字，防止换目标或换文字伪装成补发。升级前无摘要 Carrier 没有保存编辑文字，无法补做准确文字核验；为保留合法既有补发，旧格式兼容路径保留。本项不声称旧格式补发也已完成准确文字核验。
