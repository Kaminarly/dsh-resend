# 消息操作范围与持久设置 spec

Status: ready-for-review

日期：2026-10-10（Asia/Hong_Kong）。目标宿主：DSH Desktop 2.0.17。

2026-10-12 修复补充：当前宿主未提供正式输入框发送接入能力，「在正式输入框中编辑」入口停用并显示原因。关闭内联编辑器设置时仍提供临时输入框编辑，不复制普通草稿。下文对 Composer 快捷入口的原有要求以本补充及[修复记录](../../docs/session-rollback-fix-20261012.md)为准；范围限制、草稿保留和普通新消息发送规则继续生效。

本文是本轮讨论形成的增量规格，已汇总用户对 Q1–Q14 的决定，供最终确认及后续实现使用。本文中的「必须」「不得」为验收要求。本轮只编写文档，不修改、构建或安装功能代码。

## 1. 目标与范围

在现有「消息编辑」设置页中，分别控制 Regenerate 和 Edit-and-resend 是否只能操作当前有效对话中各自类型的最后一条消息。被替换消息固定隐藏；其余设置按当前 Profile 长期保存。

本需求包括：

- 两个互相独立、默认开启的操作范围限制。
- 保留重新生成按钮的显示开关，并明确其名称。
- 限制较早用户消息的内联编辑及 Composer 编辑快捷入口。
- 固定隐藏被替换消息，移除对应设置项。
- 剩余四个设置的保存、读取、失败恢复及多窗口同步。
- 按钮与实际请求处理使用同一套已保存规则。
- 已打开编辑框的状态处理及原有失败补发兼容。

本需求不增加 Branch，不实现单条答案替换后保留后续对话，不增加操作确认弹窗，不改变文件回滚功能、附件处理范围或普通 Composer 新消息发送。

### 1.1 与既有规格的关系

基础规格为 [插件规格](../dsh-resend-plugin/spec.md)；当前实现阶段的补充背景见 [实现规格](../dsh-resend-impl/spec.md)。

本文覆盖基础规格中以下旧要求：编辑可操作任意有效用户消息、重新生成始终只允许最后一条、隐藏可关闭、三个页面内设置，以及相关旧验收断言。未覆盖的 Session log、Replay turn、写入校验、序列化、错误边界、原文保留和文件回滚要求继续适用。

基于本文实现时必须同步更新被覆盖的旧测试和用户说明，不能仅保留旧断言再叠加新功能。不得为了这项需求改写无关规格或已有中文原文。

## 2. 术语与判定

### 2.1 当前有效对话

当前仍进入模型上下文的对话。Session log 保留原始记录不代表该记录仍有效；滚动位置、当前加载窗口、折叠状态及是否显示某个操作按钮也不决定有效性。

### 2.2 最后一条用户消息

当前有效对话中最新的用户本人发送的消息。排除已被替换的记录、Carrier 和宿主注入的上下文消息；图片消息等没有可编辑文字的真实用户消息仍参与最后一条判定。

因此，最新用户消息没有可编辑文字时，不得把编辑资格转移给前一条有文字的消息。最新消息本身按原有无文字条件禁用编辑。

### 2.3 最后一条助手回复

当前有效对话中最新的助手回复。按助手消息记录判断，不按 Turn 汇总，也不把工具记录或同一回复的多个显示片段视为多条回复。

用户消息和助手回复分别计算。最后一条助手回复之后新增用户消息，本身不会改变助手回复的最后一条判定；正在生成时仍按原有规则禁用操作。已被替换的助手回复不参与判定。

### 2.4 判定要求

- 按有效对话的顺序判断，不把最大 seq 或当前屏幕最下方的记录当作通用答案。
- 不得将当前历史加载窗口末尾误认成整个会话最后一条。
- 打开历史、加载更多历史、实时新增消息、编辑重发、重新生成及会话切换后均必须重新得到正确结果。
- 客户端负责按钮呈现；实际请求处理侧根据当前有效对话核验操作资格，不接受客户端自行声明「这是最后一条」。
- 当无法可靠确定操作资格时，不得先执行回退再报错。

## 3. 设置项

设置页保留四个开关，顺序与含义如下。字段名是后续实现应保持统一的配置标识。

| 顺序 | 中文名称 | 配置字段 | 默认值 | 含义 |
|---|---|---|---|---|
| 1 | 消息下方的内联编辑器 | `inlineEditorBeneathMessage` | 开 | 开启时在消息下方编辑；关闭时提供放入 Composer 的入口 |
| 2 | 显示重新生成按钮 | `regenerateLastReply` | 开 | 开启时显示重新生成按钮；关闭时全部隐藏 |
| 3 | 只允许重新生成最后一条助手回复 | `restrictRegenerateToLastReply` | 开 | 开启时限制重新生成目标；关闭时允许较早的有效助手回复 |
| 4 | 只允许编辑重发最后一条用户消息 | `restrictEditToLastUserMessage` | 开 | 开启时限制编辑目标及相关快捷入口；关闭时允许较早的有效用户消息 |

保留 `regenerateLastReply` 字段以延续现有显示设置的含义，只改用户可见名称。不得复用这个字段表示新的操作范围限制。

四个开关必须互相独立。「显示重新生成按钮」关闭时，重新生成范围设置仍可查看和修改，其已保存值不得被清除；重新显示按钮时按该值决定操作资格。

首次使用、没有保存记录或新增字段缺失时，各字段使用表中默认值。已有的合法布尔值必须保留。不得将非布尔值强制转换成开启或关闭；无效字段采用默认值，其他有效字段不丢失。配置读取失败不等同于字段缺失，失败处理见第 7 节。

### 3.1 两个范围设置的说明

两个范围设置项各自常驻显示说明，在开启和关闭状态下均可见，不以悬停提示替代。使用下列中文文案：

**只允许重新生成最后一条助手回复**

> 关闭后可重新生成较早回复。操作将从该回复对应的问题重新续接，其后的对话将退出当前上下文，原始记录仍保留。

**只允许编辑重发最后一条用户消息**

> 关闭后可编辑重发较早消息。操作将从该消息重新续接，并发送修改后的内容，其后的对话将退出当前上下文，原始记录仍保留。

说明不得被实现细节、缓存承诺或可撤销承诺替代。沿用项目现有语言切换方式，为新增名称、说明、状态及错误信息提供对应英文文案，不同时显示两种语言。

## 4. 操作规则与界面

以下表格以设置已读取、会话空闲、目标仍有效且满足其他原有条件为前提。

| 操作范围限制 | 目标 | 按钮与操作结果 |
|---|---|---|
| 开 | 最后一条对应类型消息 | 可操作 |
| 开 | 较早的对应类型消息 | 图标保留、置灰、不可点击，显示范围限制原因 |
| 关 | 最后一条或较早的对应类型消息 | 可操作 |

「显示重新生成按钮」关闭时，所有重新生成按钮隐藏，优先于表中显示规则，但不改变已保存的范围限制。

### 4.1 禁用提示

较早消息因范围限制被禁用时，悬停提示显示在图标下方，使用现有 Tooltip 风格：

- 重新生成：「只能重新生成最后一条回复」。
- 编辑相关入口：「只能编辑重发最后一条用户消息」。

必须同时做到视觉禁用和行为禁用；鼠标、键盘及旧事件处理函数均不得绕过。禁用图标的提示须可通过键盘聚焦读取。

正在生成、目标已被替换、无文字、输入框忙碌等原有保护继续生效。范围限制关闭只放开目标范围，不取消这些保护。

同一控件存在多个禁用原因时，先处理目标失效或不可读取，再处理范围限制，随后沿用正在生成、无文字、Composer 状态等原有保护。处于范围限制中的旧消息不得仅显示通用「编辑」或「重新生成」提示。

### 4.2 编辑入口覆盖

编辑范围限制必须覆盖：

- 用户消息上的内联编辑入口。
- 关闭内联编辑时，用户消息上的「在输入框中编辑」入口。
- 已打开内联编辑器中的「发送」和「在输入框中编辑」。
- Enter 提交以及其他与上述动作等价的操作路径。

不得限制宿主的普通复制按钮、手动输入或 Composer 正常发送新消息。已经通过允许的入口放进 Composer 的草稿，按普通草稿处理；后来开启限制不清空、不拦截这份普通草稿。

### 4.3 已打开编辑框的变化

当编辑框已打开，因范围设置变更或出现更新的用户消息而失去操作资格时：

- 保留编辑框及已修改文字，不自动取消、不恢复原文。
- 允许继续修改、复制和取消。
- 禁用发送和放入 Composer，并显示当前禁用原因。
- 重新满足全部条件后恢复相应操作，不清空草稿。
- 发送或放入 Composer 时必须重新检查当前资格，不能只依据打开编辑框时的结果。

保存设置或应用新配置不得通过重新挂载整段聊天界面而丢失上述草稿。这一要求不新增关闭页面、切换会话或目标已被替换后的草稿恢复功能。

## 5. 重新续接与失败补发

### 5.1 保留 Replay turn

操作不弹出额外确认框。实际执行沿用既有机制：

- Edit-and-resend：目标用户消息及其后的有效内容退出模型上下文，再发送修改后的文字。
- Regenerate：从目标助手回复对应的用户问题开始回退，再发送该问题原有文字；对应问题、目标回复以及其后的有效内容被原有机制替换。
- 原始 Session log 保留；被替换消息按第 6 节固定隐藏。
- 不得仅修改屏幕文字而保留旧内容进入模型上下文，不得创建 Branch 代替本次操作。
- 发送次数、原问题查找、引用范围、token 折叠和文件记录仍遵守原有约束。

例：当前有「问题 A → 回复 A → 问题 B → 回复 B」。关闭重新生成范围限制后重新生成回复 A，将从问题 A 重新续接，原回复 A、问题 B、回复 B 不再属于当前有效对话。编辑重发问题 A 时同理，并使用修改后的问题。

### 5.2 已回退但未发送成功

保留原有「再次发送」：

- 只适用于回退已成功而 prompt 尚未被 agent 接收的既有可补发状态。
- 后来开启范围限制，不取消此类补发资格。
- 补发只发送已经欠下的 prompt，不再次回退，不创建新的 Audit claim 或 Carrier。
- 正在生成、会话不可用及补发状态核验等原有保护继续生效。
- 普通重新生成和编辑请求不能伪装成补发来绕过范围限制。
- 本需求不承诺恢复原有未覆盖的页面刷新后编辑草稿或补发状态。

## 6. 固定隐藏被替换消息

删除「隐藏被替换的消息」开关，设置页不得显示它。隐藏改为固定行为，不再有可关闭的用户设置。

- 当前及重新打开的历史会话中，按现有 Hide plan 可识别的被替换消息都必须隐藏；不限于升级后发生的操作。
- 旧 `hideReplacedMessages` 值不再影响行为，即使旧值为 `false`。
- 不得因为改成固定隐藏而删除、重写 Session log，或改变模型上下文的回退范围。
- 消息、助手显示片段及相应工具记录等覆盖范围继续使用既有隐藏机制，不扩大为隐藏任意第三方记录。
- 关闭「已隐藏 N 条消息」提示，不得使旧消息重新出现。
- 隐藏失败时，保留并清楚显示原有错误信息；不得声称旧消息已隐藏，也不得恢复一个关闭隐藏的开关。

旧字段可在兼容读取或迁移阶段被忽略或清理，但不得重新暴露为可修改偏好。

## 7. 保存、加载与多窗口

### 7.1 保存范围与权威值

四个设置都按当前 Profile 保存。同一 Profile 的所有会话共用，不同 Profile 相互独立。页面刷新和应用重启后恢复最后成功保存的值，不增加每会话覆盖设置或跨 Profile 同步。

实际执行侧的已保存配置是权威值，客户端订阅其状态。不得让前端与执行侧各自维护互不一致的开关，也不得由单次操作请求自行指定是否绕过限制。

### 7.2 状态与失败

| 状态 | 必须呈现的行为 |
|---|---|
| 初次读取中 | 显示「正在读取设置…」；设置开关及相关编辑、重新生成、放入 Composer 入口暂不可操作 |
| 读取成功 | 使用保存值及缺失字段的默认值 |
| 保存中 | 显示「正在保存…」；防止重复写入，正式生效值仍为此前已保存值 |
| 保存成功 | 使用新的已保存值并通知所有相关界面；正常消息操作不需要额外确认 |
| 保存失败 | 恢复或重新读取权威的已保存值，显示「设置保存失败，请重试」，保留可重试入口 |
| 读取失败或权威值无法确认 | 显示「设置读取失败，请重试」；不得把失败当成首次使用而放开操作 |

初次读取期间和读取失败时，固定隐藏不依赖设置加载，继续尝试正常隐藏。普通复制、Composer 新消息发送及已核验的原有补发不因仅涉及范围设置的加载而被额外限制。

保存失败后，不能保留一个表面已关闭但实际没有保存的限制状态。若请求失败但宿主可能已写入，先读取权威状态再恢复，不能盲目假定写入未发生。

### 7.3 多窗口与执行竞态

- 同一 Profile 的其他窗口收到配置更新后，刷新其开关与操作状态；不要求所有窗口在同一瞬间更新。
- 显示开关和内联编辑设置同样同步。
- 即使某窗口尚未同步，实际请求也必须按执行时的已保存范围规则检查。
- 保留原有会话锁；在锁内确认目标及规则，在写入回退前确认仍可操作，不能仅使用排队前的结果。
- 资格不满足时，在写入任何回退事件和交付 prompt 之前拒绝，不产生部分回退。
- 配置更新不得中断已经完成回退后欠下的合法补发。

## 8. 实现约束与核对依据

本节约束正确性，具体内部文件组织可在后续实现中确定。

### 8.1 目标校验与错误

放开重新生成范围时，仍必须明确验证目标是有效助手回复。现有逻辑用「是否等于最后一条助手回复」间接保证类型，不能删掉整段后允许用户消息或 Carrier 被当作助手回复操作。

最后一条用户消息判断须排除 Carrier 和注入消息；客户端与实际执行侧保持同样语义。窗口加载、替换和新增消息后，客户端不得继续使用过期邻接关系。

保留 `not-last-reply` 表示被重新生成范围限制拒绝；为编辑范围拒绝增加明确错误 `not-last-user-message`，为非助手目标增加 `not-assistant-message`。两者需统一进入错误集合、严格结果描述、中文与英文提示及对应检查，不能只在某个处理分支临时返回未声明值。

业务错误分别提示：

- `not-last-reply`：「只能重新生成最后一条回复，请选择最后一条回复。」
- `not-last-user-message`：「只能编辑重发最后一条用户消息，请选择最后一条用户消息。」
- `not-assistant-message`：「目标不是可重新生成的助手回复，请重新选择。」

客户端按钮禁用提示使用第 4 节的短文案。其他业务错误及 Gateway 通信、依赖注入和结果解析行为继续沿用现有处理。

### 8.2 设置能力

已对安装在本机的宿主进行只读核对：

- `@deepseek-ai/dsh-settings/lib/types/index.js` 中的 `settings` 提供配置读取与更新。
- `@deepseek-ai/dsh-config-editor/lib/index.js` 的 `documentPath` 使用当前 `profileContext.patchPath`，提供按 Profile 保存的路径。
- `@deepseek-ai/dsh-client-ui-settings/lib/client.js` 的 `configForms` 提供共享状态、提交和订阅；设置文档更新与断线重连会触发重新读取。
- Desktop renderer 使用固定存储分区，不能假定裸 `localStorage` 自动按 DSH Profile 隔离。
- 本需求面向本机 DSH Desktop，不扩展远程页面只支持内存设置的模式。

后续实现优先复用宿主持久设置能力，并验证插件可被配置、配置变化不丢失草稿、页面与处理侧一致。上述能力经过代码核对，不代表已对本插件完成接入或跨窗口实测。

## 9. 验收标准

以下是未来实现必须执行的验证，不是本文编写阶段已通过的功能验证。

### 9.1 设置与迁移

1. 无保存记录首次打开，恰好显示四个开关，默认均开启；隐藏开关不存在。
2. 两个范围开关各自显示准确的常驻说明；切换开关后说明不消失。
3. `regenerateLastReply` 的名称为「显示重新生成按钮」；关闭时隐藏所有重新生成按钮，重新开启时恢复已保存的范围规则。
4. 四个设置分别修改后，刷新页面和重启应用，值均恢复；同一 Profile 新开会话使用相同值，不同 Profile 不串值。
5. 缺失字段使用默认值，合法旧值保留；无效布尔字段不会影响其他有效字段。
6. 旧隐藏值为 `false` 时仍固定隐藏，且不能通过设置接口重新关闭。
7. 读取中、保存中、读取失败和保存失败均有正确状态；保存失败不表现为未保存规则已经生效。
8. 多窗口中设置能同步；未同步窗口发起操作时，执行侧仍使用最新保存值。

### 9.2 操作范围

9. 两个限制的四种开关组合分别验证，互不影响；范围开启时只允许最后一条对应类型消息，关闭时允许较早有效消息。
10. 较早消息图标置灰且不可操作；提示文字准确，显示在图标下方，键盘可以读取。
11. 用真实宿主会话组装器覆盖打开历史、实时新增、窗口重新填充及加载更多，不仅手工构造邻接信息。
12. 回退后被替换的较晚记录不再参与最后一条判断；有效的较早记录能重新成为最后一条。
13. 最新无文字用户消息、Carrier、注入消息、多条助手消息及工具记录不会造成目标误判。
14. 关闭范围限制后仍拒绝非助手重新生成目标、失效目标、正在生成和其他原有无效条件；拒绝不写入回退事件。
15. 绕过按钮直接调用实际请求入口，仍受已保存范围限制；覆盖排队期间目标或设置变化。
16. 所有编辑入口均受限制；普通复制和 Composer 新消息发送不受影响。
17. 编辑框打开后失去资格，保留草稿，禁用发送和放入 Composer；恢复资格后可继续，不重复发送。
18. 改变设置不会重挂载并清空编辑框；已经放入 Composer 的普通草稿不被新限制清空或拦截。

### 9.3 重新续接、隐藏与补发

19. 以至少两组问答验证操作较早消息：模型输入使用正确原问题或修改文本，后续对话退出有效上下文，原始日志仍可核对。
20. 操作不弹出确认框；被替换内容固定隐藏，刷新、重启及关闭计数提示后仍隐藏。
21. 隐藏失败能看到错误，不虚报成功；附件呈现、普通消息、未被替换的对话和既有文件回滚不受无关改变影响。
22. 建立「回退成功、发送失败」状态，再开启两个限制，「再次发送」仍只补发一次，不增加第二组回退事件；普通请求不能借用该例外。

### 9.4 验证方式

- 运行 `npm run check` 和适用测试，更新宿主契约及错误描述检查。
- 相关行为测试通过后运行全量测试；实际检查失败即修复并复验。
- 使用真实宿主组装器和控件核对按钮状态、提示位置、说明排版及编辑框保留。
- 持久设置验证必须包含真实保存与重新读取、失败恢复以及至少两个同 Profile 页面；纯内存 mock 不足以证明长期保存。
- 构建后核对源码与生成产物一致。安装、重启或发布由后续任务的授权范围决定，不由本文自动触发。
