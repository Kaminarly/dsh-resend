# 设置页清理功能

Status: ready-for-human

## 已明确的需求

- 在本插件的设置界面增加清理功能。
- 只能清理与本插件相关的文件数据。
- 使用用户指定的 grill-with-docs 工作流，逐轮明确边界，记录已确认的术语和决定。
- 提供两个独立入口：「清理无用残留」和「按会话清除回滚数据」。
- 「清理无用残留」保留可识别会话的历史文件回滚数据；无法确定会话归属的回滚数据归入无用残留，允许删除。
- 「按会话清除回滚数据」列出拥有本插件回滚数据的会话，由用户选择清除目标。
- 执行前展示预计释放空间、清理范围和影响，再由用户确认执行。
- 会话选择支持多选，确认页汇总所选会话及可释放空间。
- 执行时跳过正在生成回复、编辑重发或执行文件回滚的会话，清理其他所选会话，并逐项说明跳过原因；不主动中断工作。
- 只有空清单、没有文件内容快照的会话也列入可选择清除的列表，并标注「无文件快照」。
- 两个入口均沿用先预览再确认的流程；允许删除无归属数据不改变这一流程。

## 已核实的现状

- 插件直接写入的数据位于实际 DSH_HOME 下的 plugins/dsh-resend，未设置 DSH_HOME 时使用用户目录下的 .dsh。
- records 保存历史文件回滚清单；objects 和 objects.git 保存修改前后的文件内容；outcomes 保存回滚已完成状态。
- 上述数据不全是可重建缓存。删除清单或内容会影响历史文件回滚；单独删除完成记录可能允许旧回滚再次生成恢复计划。
- 同一个 DSH 数据目录中的不同 Profile 共用本插件的数据目录。
- 宿主会话、配置、共享日志、应用缓存、已安装代码和用户工作文件不属于本功能可随意清理的插件私有缓存。
- 当前设置页提供四个开关，尚无存储清理入口。
- 现有清单和结果的名称由会话 ID、回退点 ID 的摘要生成，文件内容未直接保存会话 ID；需要通过可读取的会话日志匹配归属。
- 宿主默认会话库也位于同一 DSH 数据目录，未按 Profile 隔离，当前列表无法可靠标注最初产生数据的 Profile；自定义会话库根目录的 Profile 属于例外。
- 不同会话可能引用同一份内容对象。清除所选会话的数据时，其他会话仍引用的内容必须保留，预计释放空间不能简单累加各会话显示的内容体积。
- 当前操作锁、活动任务状态只覆盖所在 Host；按会话跳过忙碌任务和回收共享内容需要补齐跨进程协调，不能只检查当前窗口。
- 详细事实见 D:\Code\MJ-Project\dsh-resend-2\docs\runtime-storage-report.md。
- 按会话清理所需的补充事实和来源见 D:\Code\MJ-Project\dsh-resend-2\.scratch\dsh-resend-cache-cleanup\storage-facts.md。

1. 采用双入口；清空回滚数据必须细化为按会话选择清除。
2. 先预览再确认，不直接执行清理。

第二轮已确认：

3. 支持会话多选。
4. 跳过忙碌会话并处理其他所选会话。

第三轮已确认：

5. 无法归属的回滚数据归入无用残留，允许删除，不额外要求选择未知会话。

事实已确认：会话归属需通过日志匹配；存储默认跨 Profile 共用；内容对象跨会话去重；目前没有保护插件私有存储的跨进程清理锁。

三轮范围和交互决定均已记录；用户已要求实现完整方案，实施和验证已完成。

## 完整方案

### 清理无用残留

- 入口位于本插件设置页。
- 仅检查当前实际 DSH 数据目录下的 plugins/dsh-resend，不扫描或清理宿主日志、会话、设置、其他插件、安装文件和开发仓库。
- 候选项包括无法归属到会话的本插件回滚清单及结果、不再被保留清单引用的内容对象，以及已确认不在使用的遗留临时文件。
- 预览列明各类候选项数量、预计释放空间，并提示无归属回滚数据删除后不可恢复。
- 用户确认后执行；没有可清理项时显示明确的空状态。

### 按会话清除回滚数据

- 列出当前查询范围内能对应到本插件回滚数据的会话，包含未打开的历史会话及只有空清单的会话。
- 会话项显示标题、项目路径、回滚记录数量和相关体积；没有标题时使用会话 ID 作为可辨认的替代。
- 支持多选，空清单会话注明「无文件快照」。
- 预览汇总所选会话和实际可释放空间，并说明清除的是已保存的历史文件回滚数据，后续新操作仍可产生新的回滚记录。
- 执行时重新检查忙碌状态，跳过正在使用的会话；不因一条会话忙碌而取消其他可处理会话。
- 一并处理所选会话的清单、完成结果和不再被保留记录引用的内容；不会只清除完成结果。
- 清除成功后，已有文件恢复预览失效，已清除的历史数据不能通过旧预览继续恢复或被内存状态重新写回。
- 结果列出已清理、跳过和失败的项及实际释放空间，不将部分失败显示成全部成功。

### 共同约束

- 不删除会话，不修改工作文件，不重置插件设置，不卸载插件。
- 可识别且未选择清除的会话数据保持完整；共享内容只有不再被任何保留清单引用时才可回收。
- 对可识别的已保留记录无法完整读取引用时，不能以「未发现引用」为由删除其可能依赖的内容对象。
- 用户明确允许清除无归属数据；这不表示已证明该数据没有用途，预览须如实说明。
- 整体扫描失败时报告读取失败，不能把全部数据当作无归属残留。
- 清理与数据写入之间必须协调，不能删除正在保存的临时文件；预览后范围发生变化时重新核对，不扩大用户已确认的删除范围。
- 删除目标由插件确定，不接受任意文件路径；不得跟随链接清理插件目录之外的数据。

## 完成标准

- 清理范围与删除后果已经由用户明确。
- 删除路径限定在本插件拥有的数据范围内，不能通过链接或路径参数越界。
- 设置页显示与实际清理结果一致，清理失败不误报成功。
- 需要保留的历史回滚、完成状态、设置和其他插件数据有对应验证。
- 多会话共享内容、冷会话、空清单、无归属数据、忙碌跳过、旧预览失效及清理中断有对应验证。
- 实现、构建文件和说明文档一致，相关测试通过。
