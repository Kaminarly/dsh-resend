# 02 — 保存文件回滚完成状态

Type: task
Status: resolved

## 问题与根因

用户于 2026-10-11 指出：确认还原后显示「已结束」，点击「收起结果」却重新显示「预览回滚」，允许重复进入操作流程。

根因是把收起结果与清空结果共用一个处理，同时完成状态仅保存在组件内存中，Host 没有保存可查询的完成记录。原来的自动验证只检查清单是否消失，没有检查完成标记及重复入口。

## 修复

- 收起只折叠结果，保留「已结束」和「查看结果」。查看结果不发送还原请求。
- 新增 status 阶段，打开面板先读取完成状态；已完成时直接恢复紧凑结果。
- Host 保存完成标记与最终清单，按 Session 和 Carrier 身份区分；成功完成后不再生成或执行新的还原计划。
- 保存使用独立的原子替换文件；读取时按真实结果声明校验。保存失败明确列出已还原文件，后续只重试保存结果。
- 中途停止不标记成功完成，允许重新预览；新的重写点独立处理。
- 旧版本未记录的历史完成操作无法可靠推断，不补造完成标记。

## 复现与验证

修改前运行 npm test -- test/file-rollback-ui.test.mjs，新增断言确认收起后预览按钮仍存在；后台专项用例确认没有完成标记。修复后这两项检查通过。

专项验证覆盖收起与查看、持久状态加载、实际网关中的重复请求、插件重启、文件重新匹配旧后置内容、agent 正在运行、新重写点及结果保存失败后的恢复。

实际 DSH 控件验证：确认→收起→查看→刷新均保留完成状态；深浅主题和四种宽度正常。示例页使用浏览器保存演示状态，真实插件的磁盘持久化由隔离工作区和 Host 重启用例验证。

最终完整检查：114 个测试文件通过，2087 项通过，8 项原有检查跳过。语法、接口描述及已安装宿主契约检查通过；隔离 Profile 启动验证通过；11 个构建文件重新构建后逐字节一致。未修改或替换真实用户 Profile 中的安装。

验收标准已满足：收起后保持完成状态，查看结果不触发回滚，刷新和 Host 重启恢复完成记录，旧请求不重复写入文件，新重写点仍可操作，结果保存失败后只补存结果。
