# 08 — 设置、本地化与统一错误边界

规范归属：[`spec.md`](../../dsh-resend-plugin/spec.md) §10、§7.4、§7（注册点 4）、§13.3 #19–#21。规范是规范性的，本票与规范冲突时以规范为准。

**交付的端到端行为：** 三项偏好可改且立刻生效；界面按宿主语言显示中文或英文（任一时刻只有一种）；并且**没有**任何一个界面能把空白页面带回来——一个渲染期抛错只让它自己那一块变成可重试的错误行，其余照常。

## 设置

`settings.general.item`（注册点 4）承载三项偏好：

| 设置 | 默认 | 含义 |
|---|---|---|
| 隐藏被替换的消息 | 开 | 关掉后行仍然可见，只留告知行（计数披露） |
| 消息下方的内联编辑器 | 开 | 关掉后移除该行的内联编辑器，保留「在输入框中编辑」 |
| 最后一条回复上的重新生成 | 开 | 关掉后整个控件不显示 |

槽位缺失时用默认值，没有设置界面。

## 本地化

中文与英文，**绝不同时出现**——由活动的宿主语言选一个。通过 `ctx.locale` 注册；槽位 `label` 选项会投射的标签必须用 **thunk**，这样本地化文本跟随语言变化而不需要重新注册。

`TRACE_TEXT` 是唯一一条活在日志里而不是界面里的字符串：在**写入时**按活动语言选定，并记录该选择一旦写入就不可更改。

## 一个共享的错误边界

**插件注册的每一个** React 界面——动作行、内联编辑器、错误行、重新生成控件、设置行、隐藏规则元素——都必须包在**同一个共享边界实现**里，经由**同一个工厂**（例如 `withPanelBoundary(Surface, titleKey)`）传入，使得没有任何注册点直接传裸组件。

为什么这不是可选项：chat-node 组件里的渲染期抛错会被宿主的边界接住并**吞掉**。出厂参考实现就是这样丢掉了整个编辑入口——按钮不见了、设置正常、任何地方都没有错误——因为一个节点组件读了一条永远 `undefined` 的路径。那次故障看起来像「这个功能从来没做过」。

所以：一份边界实现，在所有注册点上做**函数身份**校验，每个界面带自己的本地化错误标题与一个重试控件。另加一个测试，挂载一个故意抛错的界面，断言 (a) 其它界面仍然渲染，(b) 同一个组件**不**带边界时确实把错误抛出渲染——那正是被防御的机制本身。
