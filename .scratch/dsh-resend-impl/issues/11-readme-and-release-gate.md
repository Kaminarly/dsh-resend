# 11 — README、兼容性声明与发布收口

规范归属：[`spec.md`](../../dsh-resend-plugin/spec.md) §3、§8.1、§8.6、§7.1、§12、§13.5。规范是规范性的，本票与规范冲突时以规范为准。

**交付的端到端行为：** 一个陌生人（或一个 agent）只读 README 就能知道这个包为哪个上游版本而写、兼容性由什么决定、它**有意**覆盖了平台哪一条有文档记载的行为，以及它在哪些地方会让人失望。CI 全绿，`lib/` 与源码一致。

README 必须包含：

- **目标上游版本**精确 pin（本包针对 DSH Desktop 的哪个版本、`@deepseek-ai/dsh-*` 的哪个版本），并写明**兼容性由宿主表面决定，不由 semver 决定**。
- 机制说明只能这样写：重写把该区间从模型可见表面移除；人类记录在设计上就是 append-origin、不受影响，所以插件自己隐藏了受影响的行。**不得**写成「把消息从表面上删掉」。
- 记录被用户**拒绝**的「最多隐藏 40% 对话」安全阀及其后果，用用户自己的话：大规模重写在设计上就是视觉上破坏性的，计数是用户与空白页面之间的唯一东西。
- 「在输入框中编辑」的限制：`setDraft` **只**携带纯文本，chip 占位符会被剥掉，含 `@` 引用或 `/` 命令的消息会作为字面文本回显，用户需要从触发菜单手工重建引用。升级路径（附件按 id 随草稿走、`createDrafts(sessionId, File[])` 是服务方法而非 `inputActions` 的一部分、需要用户再次提供文件对象）要**记录**，不要伪造。
- 「重写成功、重发失败」的两种情形：插件自己的错误行只覆盖**接受失败**；回合自身被接受之后的失败由 agent 自己在日志里报告，插件不重复报告。
- 注册是**一次**且由插件 fiber 持有整个生命周期：一旦 endpoint 被见到是 strict，撤回后回落就是**永久禁止**的，所以不要中途注销再注册。
- 说明包**不**提供 `./typert` 导出、**不**用 loader、**不**声明第三方契约包依赖，以及为什么（loader 需要本插件不使用的完整反射图、把解析结果缓存整个进程生命周期、且失败模式是静默跳过）。

CI 收口：

- `check` 包含源码语法、描述符校验器、宿主契约门禁三道。
- CI 顺序为 `check` → `build` → `git diff --exit-code -- lib/` → `test`；diff 门禁只在 `build` 之后才有意义，它是构建产物诚实性的保障。
- 若有任何生成文件（包括 `lib/client.bundle.js`），它们被提交进仓库，并带上 `GENERATED FILE — do not edit by hand` 横幅，点名其来源。
