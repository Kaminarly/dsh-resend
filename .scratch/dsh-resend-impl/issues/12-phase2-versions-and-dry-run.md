# 12 — Phase 2：版本基底与干跑预览

规范归属：[`spec.md`](../../dsh-resend-plugin/spec.md) §14。规范是规范性的，本票与规范冲突时以规范为准。

**前置条件：Phase 1 必须先能工作。** 只有在重写已经划定了「被撤销的工作」的跨度之后，回滚才有意义，所以本票故意排在机制之后。

**交付的端到端行为：** 每一次重写都留下一条最小、**用户不可寻址**的文件改动记录；并且在任何回滚真正执行之前，用户看到一份**干跑预览**——哪些文件会被还原、哪些会被拒绝，以及为什么。

## 版本记录，范围收窄

每次重写记录该回合碰过的文件**及其先前内容**，别的什么都不记。**没有**时间线界面、**没有**版本浏览、**没有**消息版本化——这些都在范围之外。这条记录存在的唯一目的是给回滚一个目标状态。

- **观察一个回合碰过什么**：从被撤销跨度内该回合的事件推导文件集——那些会写文件的工具行——从与票据 03 相同的**文件支撑**日志路线读取。
- **存储**：工作区是 git 仓库时 git 优先，否则回落到插件数据目录下的内容寻址快照。**永不自动提交、永不碰用户的分支。**
- 记录必须是用户不可寻址的：没有用户可达的入口能读到或改到它。

## 干跑预览

在执行之前，用户看到一份预览，它对每个文件说明：将被还原、或者将被**具名拒绝**（原因见票据 13 的分歧规则）。预览与随后的执行必须由同一份计划算出，不得各算一次。

## Answer

每次重写都会保存一条插件私有的文件记录。文件范围从被撤销跨度中的写文件事件推导，读取沿用票据 03 的文件支撑日志路线，并包含子工具调用。工具执行时保留原始字节，以避免日志展示省略内容或换行差异造成错误还原。

Git 工作区优先使用插件数据目录下的私有 Git 对象库；非 Git 工作区使用内容寻址快照。两种方式均不创建提交、不改动用户工作区的分支或引用。没有版本浏览或记录读写入口；未重写时不生成持久记录，没有目标记录时明确拒绝回滚。

重写点提供「预览文件回滚」入口，在确认前逐项列出将还原或拒绝还原的文件及原因。预览与执行共享同一份计划；确认前或执行期间发生其他文件修改时停止处理，并报告已还原与未还原的文件。缺少可靠原始内容的历史修改、失败写入和不安全路径均明确拒绝。三种回滚范围选择仍归票据 13。
