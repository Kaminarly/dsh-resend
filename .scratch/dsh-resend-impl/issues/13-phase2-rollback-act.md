# 13 — Phase 2：回滚动作与并发规则

规范归属：[`spec.md`](../../dsh-resend-plugin/spec.md) §14、§3。规范是规范性的，本票与规范冲突时以规范为准。

**前置条件：** 依赖票据 12 的版本基底与干跑预览。

**交付的端到端行为：** 用户对一次被撤销的工作选择回滚**范围**，看清后果，然后执行——而用户自己在这期间改过的文件**不会**被悄悄覆盖。

## 逐次选择

用户在每一次回滚时选择三者之一：**只回滚对话**、**只回滚文件**、**两者都回滚**。执行前看到票据 12 的干跑预览。

- 只回滚对话与只回滚文件各自独立成立，不得互相隐含。
- 任一回滚的收尾都以「明确告知哪些文件被拒绝、以及各自原因」结束——不得静默跳过。

## 并发规则（必须显式写出，不能默认继承）

规则按规范陈述，不按「默认大概是那样」：记录覆盖的是**agent 在该跨度内写过的文件**。用户并发编辑过的文件不在记录中，**回滚不得覆盖它**——在回滚时把文件当前内容与记录中的**后置状态**比对来检出分歧，对那个文件以**具名原因**拒绝，而不是把它冲掉。这是保守规则，选它是因为另一种做法会静默销毁记录从未看见过的工作。

## 接缝

Phase 2 搭同一个 Remote namespace：作为第二个 `op` 值，或一个同级方法——两者都与 §3 的接缝一致。

**Blocked by:** 12。

- [x] 执行前必展示并遵守干跑预览；用户拒绝预览时零改动。
- [x] **并发分歧可检出**：一个被记录过的文件在回滚前被外部改动过时，该文件被具名拒绝，其内容**逐字节保持不变**（有用例覆盖）。
- [x] 分歧的判定依据是文件当前内容与记录中后置状态的比对，而不是文件修改时间或任何启发式。
- [x] 未被外部改动的文件被还原到记录中的先前内容。
- [x] 每次回滚的收尾都明确列出被拒绝的文件与各自原因；不存在静默跳过。
- [x] Phase 2 接在同一个 Remote namespace 上（第二个 `op` 值或同级方法），且未破坏 Phase 1 的任何验收标准。

## Answer

重写点现在提供三种独立范围，执行前显示同一份计划的对话后果、文件处理清单和拒绝原因。用户确认「只回滚对话」的含义为撤销重写点之后新产生的对话、回到该点；该选择不还原文件，也不再次发送提示词。「只回滚文件」保留当前对话，只还原该次重写记录的文件。「两者都回滚」执行上述两项。

确认必须使用预览的原范围与原计划；更换范围需要重新预览，取消不会改动对话或文件。预览后对话增长或待还原文件变化时拒绝执行；预览中没有新对话时，执行期间新增对话也会被检出。回复在执行期间开始时停止还原，并报告未处理文件。

并发规则已明确写入 README：记录只覆盖 agent 在跨度内写过的文件，回滚逐字节比较当前内容与记录中的后置状态，不依赖修改时间。外部修改的文件具名拒绝并保留全部字节；未被外部修改的文件还原先前内容。新建文件按记录恢复到不存在的状态。

结束时显示已还原和被拒绝的文件及原因；没有被拒绝的文件时也明确说明。撤销对话导致原重写点消失时，结果保留在新重写点。对话已经撤销但保存失败时，明确说明保存尚未确认，并列出未还原文件，不把已发生的对话变化报告成零改动。Remote 继续使用同一 `resend` namespace 的 `rollback` 方法；省略范围时兼容票据 12 的只回滚文件行为。
