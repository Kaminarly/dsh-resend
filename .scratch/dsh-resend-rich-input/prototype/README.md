# 独立引用编辑器隔离原型

这是问题 01 的可运行验证，不是已安装的插件功能。原型只加载固定样例和本页接收替身，不读取真实会话、不请求模型、不写入 DSH Profile。代码、依赖和构建输出均放在本目录，正式插件的依赖与界面保持原样。

## 结论

选择 ProseMirror 作为后续临时输入框的编辑器。独立实例能保留文件引用和正文顺序，将文件显示为可删除标签，让 `/skill` 保持可编辑文字，并导出文本交给现有重发链路。依赖已经打包为浏览器脚本，使用项目现有的 `window.__ModuleLoader__.load({ id, factory })` 契约加载；模块表为空也能运行。

首选方案验证通过，无需启动替代方案。本原型保留为问题 01 的验证材料；正式接入、查询菜单与异常处理由后续问题实施。

## 运行

前置条件：Node.js 22 或更新版本。浏览器检查默认使用本机安装的 Microsoft Edge。宿主对照检查默认只读 `D:/DSH Desktop/resources/app/node_modules/@deepseek-ai`；安装位置不同时，设置 `DSH_RESEARCH_PACKAGES`。

在本目录依次运行：

```powershell
npm ci --ignore-scripts
npm start
```

浏览器打开 `http://127.0.0.1:43131`。可以删除标签、修改 skill 文字、复制粘贴、撤销、选定目录，然后点击「导出到接收替身」检查完整文本。停止服务使用 Ctrl+C。

检查命令：

```powershell
npm run check
npm run browser
```

使用 Chrome 复查：

```powershell
$env:EDITOR_BROWSER_CHANNEL = 'chrome'
npm run browser
```

## 文本规则

- 标签保存完整路径与原始引用文字；同名文件按路径区分。显示名称不会用于重建路径。
- 历史消息只有文本，没有原标签信息。本原型只把固定候选表中可以确认的路径恢复成标签，其他内容原样保留。正式接入时需要由目标 Session 的查询结果确认路径；不能把任意 `@文字` 猜成文件。
- skill 保持文字；导出后的 `/code-review /tdd /missing` 交给宿主真实加载钩子，前两个由技能替身提供正文，未知技能被宿主跳过，原消息文字保持不变。
- 继续下钻目录输出 `@"有 空格/`，仍是可编辑文字；最终选定目录输出 `@"有 空格/"`，成为标签。最终引用闭合后再加入空格，后续正文不会进入路径。
- 宿主目录补全的格式函数保留开放引号，用于继续下钻。最终目录文本增加闭合引号，符合宿主 `FILE_REFERENCE_PROMPT` 中带空格路径与目录尾斜杠的规则；真实引用 codec 对它原样导出。此验证未请求模型读取目录。
- 复制标签导出完整 `@路径` 文本，粘贴已确认路径恢复标签，未知路径保持文字。粘贴以纯文本为准；不会把剪贴板 HTML 当作可信标签来源。

## 选择依据与限制

直接使用 ProseMirror 的文档、状态、视图、历史与键盘模块，未引入宿主正式 Composer 的私有 editor，也未实例化或调用宿主 Trigger controller。宿主检查只捕获公开引用来源注册，以调用真实 codec 验证语法；浏览器编辑器不导入任何宿主包。

直接依赖已固定版本：`prosemirror-model 1.25.12`、`prosemirror-state 1.4.4`、`prosemirror-view 1.42.6`、`prosemirror-history 1.5.1`、`prosemirror-keymap 1.2.3`、`prosemirror-commands 1.7.2`。传递依赖由 `package-lock.json` 固定。模型与视图接口依据安装包源码和[官方项目文档](https://prosemirror.net/docs/)；实际运行结果以本目录检查输出为准。

本原型有意使用固定候选按钮，没有实现真实候选 RPC、完整 `@`/`/` 菜单、预览、退出草稿恢复、预检冻结或 DSH 窗口安装验收。真实中文输入法的完整组合输入、宿主 Electron 页面及不同系统剪贴板仍需在后续问题中验证。两个浏览器的成功不能代替这些验收。

本仓库使用 JavaScript，没有独立的静态类型检查命令；沿用根目录 `npm run check` 的语法、调用契约和宿主契约检查。正式生产接入时需要合并最小编辑器样式，处理已失效查询、取消操作和生命周期，并携带依赖许可。
