# 02 — 重发前按选择处理文件并继续

Status: resolved

**要交付：** 编辑重发、重新生成前，用户可以选择部分文件还原，文件决定完成后再续接会话。发生部分失败时先停下，并允许明确保留剩余文件后继续。

**Blocked by:** 01 — 历史面板多选还原与真实结果。

任务已按用户确认发布。依据已确认规格第 1、3、7–10、12–13 节。

## 验收标准

- [x] 编辑重发和重新生成共用选择规则，默认全选；「还原 N 个文件并继续」中的数量取实际选中集合，不能仍按全部可还原成员计算。
- [x] 只恢复选中成员，真实结果保存后才执行会话续接和发送；用户未选文件准确记录为保留，不被报告为已还原。
- [x] 「保留当前文件并继续」忽略勾选，保留尚未处理文件并沿用正常保留流程；零选隐藏还原按钮，仍可保留继续或取消。
- [x] 无文件变化时仍直接发送，无空面板；取消保留编辑草稿，不产生发送或新的文件处理。
- [x] 还原中禁止重复确认、修改勾选或重新查看正文；重复点击和另一选择不得启动第二次处理。
- [x] A 已还原、B 失败、C 未选时停止自动生成，显示真实结果；允许重新检查后调整剩余选择，不重复处理 A，不自动选中 C。
- [x] 用户取消全部剩余勾选后，可使用「保留剩余文件并继续」；保存真实结果与保留决定后结束回滚点再生成，保存失败则停止，结果不确定的文件继续记录为不确定。
- [x] 部分还原后取消重发不自动恢复已还原文件，不终结未完成回滚点；界面清楚说明已经发生的处理。
- [x] 文件已成功处理而会话续接、发送或其他步骤失败时，重试不重复还原、不扩大集合，不把用户保留文件报告为已还原。
- [x] 主要还原、次要保留、弱化取消的操作层级符合宿主风格；两个入口都保持原有中文及各自用途。
- [x] 使用真实工作文件和可检查的生成接收替身验证文件内容、保存结果、会话操作及发送先后顺序；覆盖子集、零选、取消、部分失败收尾和发送失败。

## 范围边界

## Answer

2026-10-13：已完成重发前按选择处理文件并继续。

接口契约：`replay` 的 `restore` 阶段可携带 `selected`（非空、唯一、属于该有效清单的成员）；前置响应允许逐成员真实结果动作 `kept`／`restored`，并携带中断记录的选择身份 `selected`（`src/typert.js`，两个 descriptor face 同步再生）。省略 `selected` 的旧调用保持原全量还原行为与旧记录格式；`keep` 只在内部调用，网关 rollback 契约不暴露（符合规格第 10 节）。

宿主执行（`src/resend.js`、`src/file-rollback.js`）：前置 `restore` 只核验、只写选中集合，真实结果落盘后才续接会话并发送（发送前断言审计与排队均为零，随后 `flush → followup`）；未选成员以 `kept` 记录。新增 `keep` 阶段：无任何落定或结果不确定成员时消费计划、沿用现有保留流程、不写完成记录；存在落定或不确定成员时按 durable journal 把尚未处理成员改写为用户保留决定，全部落定才保存版本化完成记录终结回滚点、再续接生成，保存失败即停且不发送；不确定成员保持真实状态、永不终结。未发生处理时 `plan-not-found` 被容忍并沿用正常保留流程。还原成功后会话续接或写回失败时，重试不重复还原、不扩大集合，报告逐成员 `restored`／`kept` 的真实分裂；取消不撤销已落盘文件、不终结未完成回滚点。

面板（`src/file-rollback-preview.js`、`src/resend-operations.js`、`src/client.js`）：编辑重发与重新生成共用同一组件与选择规则，首次清单默认全选；「还原 N 个文件并继续」数量取实际勾选；零选隐藏还原按钮，保留「保留当前文件并继续」与「取消重发」；还原中复选框、全选、确认与重检全部禁用，`entry.pending` 拦截重入；部分失败显示逐成员真实结果，重新检查沿用记录选择——已还原成员禁选、未选成员不被自动勾选；取消剩余勾选后按钮切换为「保留剩余文件并继续」并终结收尾；已发生处理时取消前显示原有 cancelHint。执行前提示为规格第 7 节原文（中英文对齐，含「不能从此回滚点再次还原」）；操作层级还原 primary／保留 outline／取消 ghost；两个入口原有中文保持。
