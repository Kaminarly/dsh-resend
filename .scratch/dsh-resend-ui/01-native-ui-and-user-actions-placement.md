# 01 — 用户消息编辑入口位置与 DSH Desktop 控件样式

Type: grilling
Status: resolved

## 用户反馈（2026-10-10）

用户提供三张界面截图，并要求先处理位置、提示文案和控件样式，随后再自行测试功能。

截图中的旧对话仅用于说明界面问题，不作为本轮操作指令。

## 已确定的要求

1. 编辑入口位于对应用户消息下方，与原复制图标在同一操作行、相邻排列。左右两侧均可；建议放在复制图标右侧，符合宿主现有操作行的附加操作顺序。
2. 编辑、重新生成等操作入口默认只显示图标，鼠标悬停时显示原有中文功能名称。键盘聚焦同样可以看到提示；辅助技术仍能读出名称。
3. 控件外观与 DSH Desktop 一致。复用宿主提供的控件；没有对应控件时，使用宿主已有的主题颜色、圆角、字号、间距和焦点样式。
4. 本轮完成标准是上述界面要求经过实际渲染验证。用户后续自行测试功能，不构成本轮省略界面验证的理由。

## 调查时核实的事实（修改前）

- `src/user-actions.js:164` 将编辑入口注册为独立的聊天节点；`anchorSeq = seq + 0.5` 只影响排序，不会将入口插入原用户消息的复制操作行。
- DSH Desktop 2.0.17 的 `dsh-client-ui-chat/lib/client.js:1519` 定义独立于过程分组的节点类别，自定义 `dsh-resend-user-actions` 不在其中。因此，不能仅根据半序号宣称编辑入口不会进入过程区；必须用实际对话验证。
- `src/user-actions.js:35` 和 `src/regenerate.js:167` 使用基础 `button`；`src/user-actions.js:52` 使用没有对应视觉样式的 `textarea`。当前没有为这些类名提供控件样式。
- 已安装宿主的 `dsh-client-ui-primitives` 提供 `Button`、`Tooltip`、`Input`、`Switch` 和 `SegmentedControl`。`Button` 支持 `primary`、`ghost`、`outline`、`toolbar`；宿主没有独立的多行 `Textarea` 导出，不能将单行 `Input` 当成多行编辑器。
- 宿主没有 `conversation.chat.user-actions` 槽位。原用户消息显示组件在 `dsh-client-ui-chat/lib/client.js:1446` 中创建气泡，并通过内部 `actions` 回调创建复制和时间操作行。
- `dsh-client-ui-slots/lib/index.js:263` 的 `entries(key)` 可以读取包含 `component` 的原始注册项。同一键允许不同优先级注册，数字较小者显示；同优先级会冲突。`entriesOfSlot` 只提供当前显示项，不能作为读取原始组件的替代方式。
- 原用户消息显示组件没有公开的附加操作参数。能读取原始组件不等于已经证明可以安全扩展其内部操作行；接入方式仍须原型和兼容性验证。
- 当前宿主内部 `MessageIconActions` 接收 `extraActions`，位置在复制图标之后（`dsh-client-ui-chat/lib/client.js:1164`）。候选方式是在保留原气泡与原操作回调的前提下，为其返回的 React 元素补充附加操作。该方式依赖未承诺稳定的内部元素结构；必须先验证，并处理宿主结构失配，不能作为已验证能力写进交付结论。

以上 `dsh-*` 路径均位于本机 `D:\DSH Desktop\resources\app\node_modules\@deepseek-ai\`。

`.scratch/dsh-resend-plugin/spec.md` §7.1 和 `.scratch/dsh-resend-impl/spec.md` §7.1 原先要求独立动作行、直接显示功能标签，并禁止占用原 `user` 键。用户本轮指定的相邻位置与图标提示取代其中不相符的旧要求；现已同步修订所属章节和验收项。

继续保留原用户消息的正文、附件、文件引用、技能引用、时间和复制功能。保持已有发送、取消、输入框交接及键盘行为。本轮不增加功能行为。

## 已确认的范围（2026-10-10）

### Q1 — 图标化范围

- A（建议）：三张截图中的全部操作，包括编辑器中的「发送」「在输入框中编辑」「取消」，均只显示图标；功能名称在悬停或聚焦时显示。

已确定的图标提示要求不影响正文、错误原因或状态说明。

### Q2 — 本轮样式范围

- B：本轮仅修复三张截图中的编辑入口、重新生成入口及内联编辑器。

## Answer

Q1 与 Q2 均选择 A。编辑图标接入原用户消息的操作区，位于复制图标右侧。原消息气泡、附件、引用、时间和复制操作继续由宿主显示；旧的独立编辑节点不再显示。编辑器位于同一条用户消息下方。

消息操作和编辑器操作改为图标，名称通过宿主提示控件在悬停或键盘聚焦时显示，禁用提示说明原因。按钮、提示和设置开关复用宿主控件；多行编辑器、重试与回滚区域使用宿主主题样式。回滚范围名称、预览内容和确认说明保持可见。

原用户消息接入依赖 DSH Desktop 2.0.17 的内部 React 元素结构，已用安装中的组件验证。宿主结构不匹配或扩展失败时，保留原消息并显示提示。没有新增发送、重试或回滚行为。
