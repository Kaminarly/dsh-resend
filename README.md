# dsh-resend

为 DeepSeek Harness 会话提供 Edit-and-resend 和 Regenerate：重新打开已发送的用户消息并再次发送编辑结果，或根据同一条提示再次生成助手回复。

临时输入框支持保留历史文件引用和 skill 文字，使用 `@` 选择文件或目录、使用 `/` 选择 skill，并预览宿主支持打开的资源。文件引用只传递路径，文件内容由宿主在调用时读取；查询能力缺失时保留原文和纯文本重发。草稿、候选和撤销与普通输入框隔离。关闭临时输入框后清空本次内容、选区、撤销历史、候选和提示，再次打开从该条消息原文开始；发送失败或取消文件预检时，仍保留当前打开的编辑内容。

交付包与浏览器验证见[临时输入框验收记录](docs/rich-input-acceptance.md)。开发环境可运行 `npm run acceptance:browser` 检查当前构建，运行 `npm run acceptance:bundle` 打包、解包核对并验收安装包。后者需要已安装的 DSH Desktop、Edge 和 `tar`；产物及验证证据保存在 `output/rich-input-release/`，`latest.json` 指向最新通过验收的包。完整回归另运行 `npm test`。两项验收均使用隔离环境，不安装到真实 Profile，也不向真实用户会话发消息。

**状态：契约已生效，操作可以完成，rewind 已写入，提示已发送。**

该包可以安装并加载：Host plugin 会注册 Typert 描述符表并创建 `resend` 服务，Client plugin 通过 `ctx.remote.$mount` 挂载相同的贡献。因此，`resend.apply` 从头到尾都是一个真实且严格类型化的 Remote 调用，**所有拒绝路径都已经实现**：对于任意输入，它都会返回十四种代码中正确的一种，包括空 Session 或未知 Session、缺少 agent 或 agent 正在流式处理、从未存在过的目标、仍处于 pending 状态的目标、已经 rewind 的目标、消息类型错误、范围限制、空白编辑，以及仅包含图片的提示。

Host 在插件启动时只注册一次描述符，由插件 fiber 持有整个生命周期；仅在 fiber 结束时，由宿主的 effect disposer 撤回注册。一旦 endpoint 被见到是 strict，撤回后回落到反射路径就会被**永久禁止**，调用会以 `gateway/definition-unavailable` 失败。因此，不要在插件运行期间注销再注册。

范围和 resend 文本通过覆盖范围的日志读取解析，再使用官方的 `foldSurface` 进行折叠。界面操作先检查文件改动，有改动时等待用户选择；确认继续后才写入 rewind。rewind 由一对事件组成，即 audit claim（`compaction/prune`）和 carrier（携带 `surfaceOp` + `sourceEventSeqs` 的 `user/message`），两者在第一次 append 前通过宿主自己的 replay 一起校验，随后相邻追加，并且只 flush 一次。Carrier 不渲染；被替换的范围会离开 model surface，但仍留在 Transcript 中；audit claim 携带**官方** shadow price，因此宿主自己的 token fold 会扣除该范围，而不会静默地高估。

**resend 也已经生效。** flush 完成后，提示会通过 `agent.followup` 排入 agent 队列，结果 envelope 会报告已排队消息的 id。该消息是用户唯一能看到的新行，因为 carrier 不渲染。`followup` 是 fire-and-forget 调用并返回 `undefined`，因此唯一的接受信号是紧接调用后读取的 `agent.status`：如果 agent 没有接收提示，rewind 会保留，envelope 只会省略该 id。此时 Client 会在 rewind point 渲染错误行，并提供「再次发送」按钮；按下按钮会重放同一个请求，Host 会重新发送提示，但**不会执行第二次 rewind**。如果 agent 已接收 Turn、之后才失败，这不属于本插件的报告范围，agent 会在 Transcript 中自行报告。

按钮提供的重试只在记录该状态的页面加载期间有效，因为它所重放的请求（包括编辑后的消息文本）按设计保存在 Client 状态中。Client 在原用户消息下方的复制图标旁显示编辑图标，并隐藏被 rewind 覆盖的行。编辑、重新生成和取消操作仅显示图标，悬停或键盘聚焦时显示相应提示；发送按钮显示图标和「发送」文字。临时输入框占满消息区域宽度，输入区默认三行，并随文本内容自动增高，打开时光标位于文本末尾；外层圆角框同时包住「临时输入框」纯文本标题和输入区，关闭按钮位于外框右上角，右下角发送按钮采用与正式输入框一致的蓝色。「在正式输入框中编辑」入口已移除。

文件和技能标签左侧显示图标，右侧分别显示完整文件路径和不含开头「/」的技能名；普通文字与两种标签对齐。技能确认在后台进行，不显示输入期间的等待提示。技能格式、可用性、文件查询和预览异常以 12px 红字显示在整个临时输入框下方，不占用编辑区，也不改变圆角框高度。已有匹配候选时，不把当前尚未输入完的技能名提示为格式错误；关闭候选后仍会按完整文字检查。

文件和 skill 菜单悬浮在临时输入框蓝色边框的上方，使用 DSH Desktop 正式输入框的菜单背景、阴影、行高、圆角和选中效果。文件候选显示名称、图标和所在目录，skill 候选显示名称和右侧说明。方向键和鼠标移动切换选中项，Enter 选择，Tab 对目录执行下钻、对其他候选执行选择；目录导航可返回上级，Shift+Tab、Escape 或点击框外关闭菜单。skill 查询复用宿主的模糊排序；查询仍有可选候选时，不把正在输入的缩写提示为失效技能。普通草稿、撤销和附件保持独立。

按钮、提示和设置开关复用 DSH Desktop 控件，多行编辑器和回滚区域跟随宿主主题。当前消息接入已在 DSH Desktop 2.0.17 验证；宿主消息结构不兼容时保留原消息并显示原因。正式输入框尚无公开的发送接入口，过去仅复制文字会使下一次发送变成追加消息。因此编辑入口统一使用临时输入框，保留原消息目标；「显示编辑重发按钮」控制入口是否显示。临时输入框支持文件引用菜单和 skill 选择，不提供上传附件编辑。

文件清单使用真实工具结果的 `toolCallId` 和 `source.callId` 关联修改记录，并兼容历史字段及明确的事件引用。缺少结果、关联冲突或缺少原始快照时，会列出无法可靠还原的文件，等待选择；无法读取修改参数时停止重发。只有确认没有文件变化，才跳过面板。原始快照丢失后不会根据当前文件猜测历史内容。

助手回复的操作栏保留重新生成图标。开启范围限制后，较早回复的图标禁用，悬停或键盘聚焦时显示「只能重新生成最后一条回复」；关闭范围限制后，较早的有效回复也可操作。关闭「显示重新生成按钮」后，所有回复下方的该图标都会隐藏。

如果未来的集成需要保留附件，支持的升级路径是让附件按 id 随草稿走：通过附件服务的 `createDrafts(sessionId, File[])` 创建草稿附件，再将生成的 id 交给 `inputActions.addAttachments(ids)`。`createDrafts` 是服务方法，不是 `inputActions` 的一部分；用户需要再次提供文件对象，插件不能从历史消息的附件 id 还原 `File`。本插件尚未实现这条升级路径，不会自行创建或持久化这些文件。

重写（rewind）把该区间从模型可见表面移除；人类记录（Transcript）在设计上就是 append-origin（以追加来源为准）、不受影响，所以插件自己隐藏了受影响的行。隐藏规则由 React 渲染的 CSS 提供：这是插件有意覆盖平台有文档记载的展示行为。用户可以关闭计数通知，但其样式规则仍会保持挂载，以确保隐藏的行不会重新出现。

被替换消息固定隐藏，设置页不再提供「隐藏被替换的消息」开关，旧设置为关闭也不会恢复显示。重新打开历史会话后，插件仍会隐藏现有隐藏计划可识别的旧消息、助手显示片段及对应工具记录。隐藏不依赖设置读取或计数通知；原始 Session log、模型上下文的回退范围和文件回滚规则保持原样。

用户已拒绝此前提议的「最多隐藏 40% 对话」安全阀，其后果是：**大规模重写在设计上就是视觉上破坏性的，计数是用户与空白页面之间的唯一东西。** 在长 Session 的顶部附近进行重写，可能隐藏几乎整个 Transcript；重写位置的通知会显示实际隐藏的行数。隐藏计划失败时，会在受影响的行和诊断日志中报告，而不会悄悄留下不一致的视图。

「消息编辑」设置页提供「显示编辑重发按钮」「显示重新生成按钮」「只允许编辑重发最后一条用户消息」和「只允许重新生成最后一条助手回复」，前两个开关默认开启，后两个范围限制开关默认关闭。关闭显示开关时，隐藏对应按钮，并禁用对应的范围限制选项；两个显示开关分别控制自己的范围限制，互不影响。禁用时保留已保存的限制值，重新开启显示开关后恢复可调整。旧「消息下方的内联编辑器」选项已移除，旧值不会被转成隐藏按钮的设置。设置按当前 Profile 保存，同一 Profile 的会话共用，刷新页面和重启宿主后恢复；不同 Profile 各自保存。读取中或读取失败时，编辑和重新生成入口暂不可用，普通复制、新消息发送和已核验的合法补发不受影响。保存期间继续使用此前已保存的值，成功后同步到同 Profile 的其他页面；保存失败会重新读取保存值并显示重试入口。切换设置不会清空已打开编辑框的文字。

其他窗口尚未同步时，旧按钮发起的操作仍按最新保存规则核验，不符合条件时不会回退或发送。断线重连会重新读取完整有效对话的操作资格；聊天记录尚未重新载入时，也不会根据旧消息位置恢复操作。读取期间保留已打开的编辑草稿。

已经回退成功、agent 尚未接收的 prompt 可在两个范围限制开启后继续补发，只交付欠下的原内容，不再次回退。agent 已接收的 prompt 不再提供补发，即使对应消息还未写入 Session log；其他目标或不同的编辑文字也不能冒充新记录的补发。此规则不新增页面刷新后的草稿或补发状态恢复承诺。

重新生成范围限制开启时，较早回复的图标保留并置灰，鼠标悬停或键盘聚焦时在下方显示「只能重新生成最后一条回复」。最后一条按当前有效对话中的助手消息判断，后续用户消息、工具记录和历史窗口的位置不会改变这一判定；无法确认有效对话时暂停重新生成，并提供重试入口。

范围设置始终显示以下说明：「开启后，仅可重新生成最后一条助手回复；关闭后，则允许重新生成较早的助手回复。操作将从所选回复对应的问题重新续接，其后的对话将退出当前上下文。」操作沿用 Replay turn，有文件改动时先展开文件面板等待选择，不创建 Branch。「显示重新生成按钮」关闭时隐藏全部重新生成按钮，保留已保存的范围值。关闭范围限制后，正在生成、已被替换、没有可重发文字和非助手目标仍不可操作；直接调用请求同样受执行时已保存规则约束。回退成功但尚未发送的问题仍可按既有「再次发送」补发，不再次回退。

编辑范围限制开启时，较早用户消息的编辑图标保留并置灰，悬停或键盘聚焦时在下方显示「只能编辑重发最后一条用户消息」。最后一条按整个有效对话判断，排除被替换记录、Carrier 和宿主注入；最新无文字用户消息仍参与判断，不把资格转给前一条有文字消息。范围设置常驻显示：「开启后，仅可编辑重发最后一条用户消息；关闭后，则允许编辑重发较早的用户消息。操作将从所选消息重新续接，并发送修改后的内容，其后的对话将退出当前上下文。」

限制同时适用于内联编辑、发送和 Enter 提交。已打开编辑框因新消息或设置变化失去资格时保留草稿，仍可修改、复制和取消；恢复资格后可继续发送。正式输入框的普通草稿不会被编辑操作覆盖。编辑较早消息会发送修改后的准确文字，后续对话退出模型上下文，原始日志仍保留；合法的失败补发不受后来开启范围限制影响。

四设置的逐项验证及验证边界见[整体验收记录](docs/action-policy-acceptance.md)。整体验收阶段使用隔离 Profile 的实际保存服务和会话处理，以及已安装 DSH Desktop 的真实控件；未在该阶段安装到用户 Profile、重启用户应用或连接外部模型。升级前没有保存编辑摘要的旧 Carrier，仍沿用既有补发兼容路径，无法核验旧编辑草稿的准确文字；新记录会核验目标和文字，拒绝冒充补发。

## 文件回滚预览

两个入口均支持逐文件多选和「查看差异」。首次默认选中全部可还原文件；查看未选文件不会改变勾选。清单分别显示选中还原、用户选择保留和系统无法还原的数量。一次成功确认会结束整个回滚点，未选文件不能从同一点补还原。历史面板零选时只提供关闭；重发前零选时仍可保留文件并继续。

正文弹窗按「当前内容 → 还原后内容」显示同列差异、行号和删除／恢复图例，新增文件明确提示还原后删除。超过正文限制时说明原因，仍允许选择原本可还原的文件；文件变更导致清单失效时需重新检查。弹窗跟随宿主主题和字号，路径与代码分别在内部滚动；关闭正文保留选择，并返回原查看入口。

已确认规格及整体交付证据见[文件回滚整体交付验收](docs/rollback-delivery-acceptance.md)。可运行 `npm run acceptance:rollback:visual` 验证宿主控件和布局，运行 `npm run acceptance:rollback:browser` 验证临时真实文件与浏览器的组合场景，运行 `npm run acceptance:rollback:bundle` 打包、解包核对并验收交付字节。这些检查不会替换用户安装或请求外部模型。

编辑重发和重新生成都会先检查目标消息对应的文件改动。没有记录到文件改动，或已确认修改前后内容相同的文件相互抵消时，直接撤回旧对话并发送消息，不展示文件回滚面板。

有文件改动时，在原提问之前展开现有「文件回滚」面板。旧对话保留，助手等待用户选择「还原 N 个文件并继续」「保留当前文件并继续」或「取消重发」。还原选项先处理预览中可还原的文件，再撤回旧对话并发送消息；保留选项不改动文件，直接继续；取消不撤回对话、不发送消息。缺少可靠原始内容或已被用户修改的文件仍会具名列出并保留，不会将无法还原误判为没有文件改动。原提问不在当前历史窗口中时，以悬浮面板提供相同选择。

预览后文件发生变化、助手开始运行、对话范围变化或回滚数据被清除时，恢复操作会被拒绝。文件变化可重新预览；对话或记录变化后需取消重发，再重新操作。恢复中断时不撤回旧对话，也不发送消息；重新预览会保留此前已还原或结果不确定的文件。若文件已经还原但撤回对话失败，可继续重发，重试不会重复还原；此时取消重发会保留已经还原的文件。发送失败后的「再次发送」仍只补发原消息，不再次恢复文件或撤回对话。

前置选择使用 `resend/replay`：`start` 检查并预览，`preview` 刷新文件清单，`restore` 或 `keep` 完成重发，`cancel` 结束等待。消息文字及处理范围由 Host plugin 保存，确认请求只携带会话和计划标识。前置计划属于当前 Host plugin 的临时状态；刷新页面或重启不会自动继续发送。新的按钮操作会淘汰同一 Host plugin 中该会话的旧预览，旧页面不能继续执行原计划；重启后旧计划失效，重新操作会按现有记录检查文件。既有 `resend/apply` 保留原调用和失败补发兼容性，新界面操作始终先调用 `resend/replay`。

每次重写都会保留受影响文件的最小内部记录。已完成重写点的历史「文件回滚」面板默认只显示标题、说明和「预览回滚」按钮；点击后展开文件清单，列出可还原的文件及无法还原的具体原因。文件名称、所在目录和处理状态分别显示。确认前不会改动文件；取消会丢弃本次预览。无文件改动的重写点不显示历史面板；重发前已成功还原的重写点显示已完成状态。

插件观察到的文件写入会在工具执行结束时保存修改前后的内容和对应记录。即使尚未打开文件回滚预览，关闭会话或重启 DSH Desktop 后，重新操作仍可读取这些记录并检查还原条件。取消预览不会删除已保存的文件内容；「清理无用残留」会保留可识别会话依赖的内容，「按会话清除回滚数据」会清除所选会话的对应记录。旧版本仅保存在内存中、重启后已丢失的原始内容无法补回；用户后来修改过的文件仍保留当前内容。

面板只提供文件回滚，保留当前对话，不撤销消息，也不再次发送提示词。「确认还原 N 个文件」只处理预览中可还原的文件；没有可还原文件时不显示确认按钮。确认使用预览生成的同一份计划；预览后待还原文件发生变化时拒绝执行，并提供重新预览入口。结束时显示已还原和未还原的数量、文件清单及原因；若执行期间后续文件发生变化，会停止并报告已经还原与未还原的文件。结果可收起，面板回到紧凑布局并保留「已结束」及「查看结果」，不会再次提供预览或确认还原。

文件回滚成功结束后，完成标记和结果清单保存在插件数据目录中。重新打开会话、刷新页面或重启后，面板先读取已保存状态；已完成的重写点只提供查看结果，后台也不会为它生成第二份还原计划。未完成或中途停止的回滚仍可重新预览。若文件已经还原但结果保存失败，会明确报告；恢复存储后只重试保存结果，不重复还原文件。旧版本没有留下完成记录的历史操作不会被推断为已结束。

已结束的结果清单中，已还原文件提供「查看还原内容」。弹窗按行展示本次实际还原的内容及格式信息，读取已保存的还原目标，不随工作文件后续修改变化；刷新、重启和助手继续生成时仍可查看。删除文件与空文件分别显示明确说明，用户选择保留、无法还原或结果不确定的文件不提供入口。正文超过 3 MiB、10,000 行、单行 20,000 个 Unicode 码点或不是可展示的 UTF-8 文本时，仅说明原因；相关记录被清理、丢失或损坏时明确报告无法读取。查看不会改动文件、触发生成或重新开放回滚点，也不额外保存正文副本。

独立的对话回滚及同时回滚对话和文件的功能已移除。Remote 的 `rollback` 请求保留省略 `scope` 或指定 `artifacts` 的文件还原调用，拒绝 `conversation` 和 `both`；`status` 阶段用于读取完成状态；上次结果未保存时仅补存结果，不创建还原计划、不修改文件或对话。编辑重发和重新生成所需的 Replay turn 机制继续保留。

记录只覆盖 agent 在被撤销跨度内写过的文件。回滚逐字节比较文件当前内容与记录中的后置状态，不使用修改时间判断。用户修改导致内容不一致时，保留当前文件并具名拒绝还原；未被记录的文件不会被处理。

文件集来自覆盖日志中被撤销的工具结果及对应调用，包括 `run_code` 里有日志记录的第一方子工具写入。插件在 `write`、`edit` 和 `str_replace_editor` 的写入命令执行前后读取原始字节，保留第一次写入前的内容及最后一次写入后的内容，并检查观察期间是否出现其他修改。日志里已有的旧调用若缺少可靠的原始内容，会在预览中明确拒绝，不会用 Git HEAD 或展示用差异猜测。观察值在插件运行期间保留；重写完成后的记录持久保存，重启后仍可预览和还原。Shell 命令与第三方工具的任意文件写入目前不在可识别的文件集内。

Git 工作区使用插件数据目录内的私有 Git blob 存储，不产生提交、不修改用户的 HEAD、分支或暂存内容。非 Git 工作区使用内容寻址快照。内部记录包含文件路径、前置与后置内容引用，或无法还原的原因；新记录还保存所属会话和重写点标识，用于识别清理范围。没有读取原内容、编辑记录、时间线或版本浏览入口。记录保存在 `$DSH_HOME/plugins/dsh-resend/`（未设置时使用 `~/.dsh`）。符号链接、工作区外路径和 `.git` 内的文件会被拒绝。

## 回滚数据清理

「消息编辑」设置页提供两个入口，均先展示清理范围、预计释放空间和影响，再由用户确认执行。

- **清理无用残留**：清理无法确认会话归属的回滚清单及完成结果、不再被保留清单引用的文件内容，以及已确认不在使用的遗留临时文件。无法归属的数据可能仍有用途，删除后无法恢复。可识别会话的历史回滚数据保留。
- **按会话清除回滚数据**：列出当前查询范围内拥有回滚数据的会话，支持多选，包含未打开的历史会话。只有空清单的会话标注「无文件快照」。确认页合并计算共享内容，预计释放空间可能小于各会话相关体积之和。

清理仅处理当前实际 DSH 数据目录下本插件拥有的数据，不删除会话、不修改工作文件、不重置设置，也不清理其他插件、共享日志、安装代码或开发仓库。同一数据目录可能由多个 Profile 共用；自定义会话库不在当前查询范围内的旧数据可能无法识别归属。

执行时重新检查会话状态，跳过正在生成回复、编辑重发或执行文件回滚的会话，继续清理其他所选会话。结果分别列出已清理、跳过和失败项及实际释放空间。预览后发生变化的数据保留，需重新预览；部分保留清单无法完整读取时，文件内容暂不回收。整体读取失败会停止清理。

清除会话的历史文件回滚数据后，已有恢复预览失效；原有内存记录不会重新写回已清除的数据。后续新操作仍可生成新的回滚记录。预览有效期为 15 分钟，取消或执行后即失效。跨窗口协调要求使用本版本的 Host plugin；升级后应重启仍运行旧版本插件的 DSH 窗口。

验证范围和存储保护细节见[清理功能验收记录](docs/cache-cleanup-acceptance.md)。

## 目标上游版本

| 目标 | 版本 |
|---|---|
| DSH Desktop | `2.0.17` |
| `@deepseek-ai/dsh-*` | `0.2.0-rc.2` |
| `@deepseek-ai/cordis` | `4.0.4` |

兼容性由**宿主表面（host surface）决定，不由 semver 决定**：插件会读取已安装 Host 实际暴露的成员；当当前断言的某个成员缺失或形状发生变化时，`npm run check` 会失败。`package.json` 中的 `peerDependencies` 范围是 DSH 评估时强制使用的机制（带有 `includePrerelease`），并且范围有上下界；如果运行时不满足 peer 范围，DSH 会报告 `incompatible-version`。上表是本包**验证过**的版本组合，也是开发依赖锁定的版本组合；peer 范围有意设置为更宽的下限，因为如果范围排除了仍能运行该包的 Host 版本，Loader 会静默跳过该 Bundle。

本包不提供 `./typert` 导出，也不使用 Typert loader 注册描述符。该 loader 需要本插件不使用的完整反射图（`model`），把解析结果与导入的清单缓存到整个进程生命周期，且失败模式是静默跳过；事后补上导出还需要重启应用。直接调用 `ctx.typert.register()` 避开了这些限制。这里的 loader 指 Typert 描述符 loader；插件本身仍通过 `cordis.patch.yml` 加载，浏览器脚本仍通过模块加载器注册。

本包不声明第三方契约包依赖：描述符与写入规则由本包实现，并用宿主自己的校验器和 replay 验证；运行时依赖只有 `zod`。Host 注册和 Client 挂载都通过 `ctx` 访问宿主服务，Client bundle 不直接导入 Typert registry。

## 目录结构

```
package.json            一个 npm 包 = 一个 Bundle
cordis.patch.yml        Profile Bundle 补丁层（一个 Loader 行）
src/                    手写源代码
lib/                    已提交的构建产物（不要手动编辑）
scripts/build.mjs       从 src/ 重建 lib/（esbuild）
scripts/check-*.mjs     三个门禁脚本
scripts/probe-profile.mjs  启动隔离 Profile 并验证两侧
test/                   vitest 测试套件
```

`lib/` 是生成目录，当前全部 11 个生成文件（含 `lib/client.bundle.js`）均已提交到仓库。每个文件都带有 `GENERATED FILE — do not edit by hand` 横幅，点名对应的 `src/` 来源和构建脚本。CI 会在运行 `npm run build` 后立即执行 `git diff --exit-code -- lib/`，以证明它与源代码一致；diff 门禁只在 build 之后才有意义，是构建产物诚实性的保障。

CI 在同一个任务内依次执行 `check → build → git diff --exit-code -- lib/ → test`，任一阶段失败即整体失败。

## 开发

```
npm install
npm run check     # 1. 源代码语法  2. 描述符校验  3. Host 契约
npm run build     # 重建 lib/
git diff --exit-code -- lib/  # 构建之后确认已提交产物与源码一致
npm test          # vitest 测试套件
npm run probe     # 启动隔离 Profile 并验证两侧（仅限 Desktop）
```

门禁包括：

1. **`scripts/check-syntax.mjs`** —— 使用打包器自己的解析器解析 `src/` 和 `lib/` 下的每个 JavaScript 文件；这样在 build 之前，源码和已提交产物中的语法错误都能被发现。（普通的 `node --check` 只会静默校验第一个参数，因此这里必须遍历目录。）
2. **`scripts/check-typert.mjs`** —— 通过已安装的 `@deepseek-ai/dsh-typert-registry` 校验器驱动 Typert 描述符的两侧，而不是重复实现校验规则，因此门禁会随 Host 变化。脚本通过逐项修改真实贡献的副本来断言 §6.3 的七条规则：每次破坏一个字段，校验器都必须根据对应规则拒绝；同时使用接受探测作为正向对照。两条注册路径都会被驱动（Host 侧使用 `ctx.typert.register`，Client 侧使用 `ctx.typert.remotes.register`），并读取实际运行的两个产物，再与两侧进行比较（`lib/index.js` 中的注册和 `lib/client.bundle.js` 中的挂载），因为只验证没人发布的侧面没有意义。描述符表为空时会失败：没有内容可供断言，脚手架所需的 `--allow-empty-descriptors` 让步已经移除（现在传入该参数会以用法错误退出）。
3. **`scripts/check-host-contract.mjs`** —— 直接读取已安装的 DSH Desktop 应用（`app.asar` 或未打包的 `resources/app`），不联网、不改动 Profile；断言表在 `scripts/host-contract.mjs`，它按**声明该成员的 Host 实体**（类）而不是按文件来组织，因为 `events`、`append`、`get` 这类名字在打包产物里到处都是。两个方向都会被断言：插件读取的每个成员必须仍在（PRESENT），上游已移除的成员必须保持消失（ABSENT，即复活警报），插件两侧按名字导入的绑定同样会被检查（改名的导出会让 Host 侧加载即报错、让浏览器 Bundle 静默失效）。三条规则与断言同等重要：文件、包清单或 Slot 目录项找不到算漂移而非通过；反向断言宁可过度匹配——类字段、getter、方法、构造函数赋值、对象字面量属性，以及 `Object.assign(X.prototype, …)` / `Object.defineProperty` / 计算成员这类挂载式写法都要匹配，连无法枚举成员的 `Object.assign(X.prototype, methods)` 也算；此外还有一条插件侧不变量，扫描 `src/` 与 `lib/`，除日志读取模块外任何文件读取 legacy 事件视图成员（包括 `session["events"]` 这种计算写法）都会以 `file:line` 失败。读取器内置在 `scripts/asar.mjs`（不引依赖），并在打开任何路径之前设置 `process.noAsar = true`，因为 DSH Desktop 在 Electron 的 Node 下运行包脚本，其 asar 包装会拦截以 `.asar` 结尾的路径。没有安装应用时，脚本会打印明确的 `SKIP` 并以零退出，因为该门禁对 Desktop 是可选的；这也是它在 CI Runner 上会显示为「绿色但为空」的原因。

`npm run probe` 是唯一无法在没有安装包的环境中运行的检查：它会在 `.tmp/` 下创建临时 `DSH_HOME`，把本包安装到 `probe` Profile，在操作系统分配的端口上启动已发布的 Launcher，并断言 Host 审计保持静默（没有遗留 pending 项）、提供的 Web 启动图包含 Client 行，以及提供的 Bundle 会自行注册。它从不接触真实的 `$DSH_HOME`，没有安装应用时会打印 `SKIP`。

`node scripts/preview-ui.mjs` 提供本地界面验证页：使用已安装 DSH Desktop 的实际 React、消息气泡、控件和主题样式，加载当前构建。页面使用示例消息和模拟操作，不读取真实会话，也不会发送模型请求或改动用户文件。可用 `?dark`、`?busy` 检查深色主题和运行中禁用提示；窗口缩窄后检查布局。

设置 `DSH_APP_ROOT`，可让门禁（以及 probe）指向指定安装：既可以是未打包的 `resources/app` 目录，也可以是 `app.asar` 路径。

`zod` 是本包唯一的运行时依赖：描述符的严格 codec 使用 zod schema，这是 Typert 要求 `create()` 工厂提供的内容。这些 schema 使用 `zod/mini` 编写——它与 zod 核心相同，只是采用函数式写法——因为两侧都从同一张表派生，所以构建这些 schema 的内容也会被打包进浏览器脚本；经典入口会把 Client 永远不会调用的函数连同约 750 KB 的 zod 一起放入 `lib/client.bundle.js`（规范 §16.5）。

`@deepseek-ai/dsh-api-gateway` 是 devDependency，而不是 peer：已发布代码不会导入它（Client 侧通过 `ctx.remote` 访问它，`dsh.client.inject` 只负责安排它到达的顺序）。将它锁定，是为了让描述符规范在 CI 中驱动真实的 consumer——mount、dispatch、envelope——而不只是依赖安装了应用的机器。

`@deepseek-ai/dsh-util-crypto` 同时是 peer 和 devDependency：已发布的 Host 侧会导入它的 `randomUUID`，用来生成 carrier 和 resend message 所使用的标记 id，因为 id 是插件可以存放标记身份的唯一位置（规范 §5.4）。这是 Host 自己的包生成消息时使用的模块，也正因如此，本包不会直接调用 `crypto.randomUUID`——该 Web API 在安全上下文之外不可用，而该模块自己的文档记录了这一点。

`@deepseek-ai/dsh-token-meter` 仅是 devDependency，有意不设为 peer：已发布代码不会导入它，而是通过 `ctx.get('tokenMeter')` 解析 meter，并从服务获取官方 estimator（规范 §5.3），这样 audit claim 的价格就是 Host 自己 fold 会扣除的数值。测试套件会导入同一个包的 estimator，独立检查该价格；缺少 estimator 时，测试套件会抛错而不是跳过。

`react` 和 `react-dom` 均为 peer，由宿主浏览器的模块表提供。插件用 `react-dom` 的 `createPortal` 将重新生成的错误提示显示在会话裁切区域之外，并保留设置面板原有的挂载位置；不会打包第二份 React。`jsdom` 仅为 devDependency，用于验证错误边界、消息操作和设置页。渲染异常是否能被局部隔离，需要在实际 React DOM 环境中检查；服务端渲染器无法替代这项验证。

`node-addon-require-builtin` 是一个没有任何导入位置的 devDependency：它是 cordis 的可选 peer；只有存在该包，Loader 才能像 Profile 启动时那样，从 base URL 解析裸包名。启动测试套件会断言该路径可用，而不是伪造它。

## 安装到 Profile

### 手动安装本地插件（DSH Desktop）

本地安装使用 `.tgz` 包，无需将插件发布到 npm。已拿到安装包时，直接执行下面的安装步骤；从源码打包时，先在本仓库目录运行：

```powershell
npm ci
npm run check
npm run build
New-Item -ItemType Directory -Path "D:\DSH Desktop\plugins\dsh-resend" -Force
npm pack --pack-destination "D:\DSH Desktop\plugins\dsh-resend"
```

`npm pack` 会打印生成的包名，例如 `dsh-resend-0.1.0.tgz`。安装时使用生成文件的绝对路径。将安装包保存在固定目录；安装记录会引用这个路径，后续重新安装时仍需使用它。

1. 打开 DSH Desktop，在侧栏选择「插件」。
2. 如果已安装 `dsh-resend`，先在插件页卸载旧版；首次安装跳过这一步。
3. 选择「添加插件」，在包名输入框中粘贴本地 `.tgz` 文件的绝对路径。不要附加引号或 `dsh plugin add` 命令。
4. 选择「安装」，等待完成；需要排查失败原因时，展开「查看安装详情」。
5. 选择「立即启用」。如果已关闭安装对话框，在插件列表中找到 `dsh-resend` 并开启它。
6. 重新打开会话，检查用户消息下方是否出现编辑图标。如果当前页面仍显示旧界面，刷新页面或重启 DSH Desktop。

本次界面修订包的路径为：

```text
D:\DSH Desktop\plugins\dsh-resend\dsh-resend-0.1.0-ui02-20261010.tgz
```

升级本地包时，重新构建并打包，按上述步骤卸载旧版、安装新包。即使版本号相同，也应使用新文件名区分不同构建，避免继续读取旧包。

### 命令行安装

通用 DSH 启动器适用于普通 Profile：

```text
dsh plugin --profile <name> add dsh-resend
```

本地包可将最后的包名替换为 `.tgz` 文件的绝对路径。

DSH Desktop 2.0.17 的 `desktop` 配置由应用管理。直接运行通用 DSH 启动器会返回 `profile "desktop" is managed exclusively by the Electron application`；桌面插件的手动安装优先使用上面的应用插件页。

应用自带的 DSH 命令入口支持桌面配置，需要同时使用应用自带的 pnpm 环境。在 DSH Desktop 打开的终端中，可运行：

```text
dsh plugin --profile desktop add "D:\DSH Desktop\plugins\dsh-resend\dsh-resend-0.1.0-ui02-20261010.tgz"
```

命令完成后重新打开会话；页面仍显示旧界面时，刷新页面或重启 DSH Desktop。普通 Profile 则重启对应的 `dsh` 进程。
