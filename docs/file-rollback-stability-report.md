# 文件回滚稳定性报告

日期：2026-10-11。审查对象：当前工作区的 DSH Resend Bundle，包括本次优化后的源码与重新生成的 `lib/`。工作区已有未提交改动，本次以当前内容为基线，没有回退这些改动，也没有替换真实 Profile 中已安装的插件。

## 结论

文件回滚已具备正常使用、预览失效、部分失败、插件重启及多窗口协作所需的主要保护。本次补上了安全写入、特殊文件拒绝、Git 快照核验和持久恢复进度。新增 17 项回归用例，全量 2134 项测试通过，8 项按环境跳过；宿主隔离启动验证通过。

建议将其定位为**先确认、逐文件执行、遇到不确定结果时保留当前文件**的恢复功能。多文件恢复不是一次全成功或全撤销的事务；任意外部程序与最终文件替换之间也没有操作系统提供的条件更新保证。不能将其解释为项目的完整备份或任意修改的撤销工具。

## 功能范围与实现流程

入口位于 Rewind point 的文件回滚面板。这里只恢复文件，不修改 Session log，也不补发提示词；移除的 `conversation`、`both` 范围仍由严格请求解码拒绝。

| 阶段 | 当前行为 | 主要文件 |
|---|---|---|
| 观察工具写入 | 拦截 `write`、`edit`，以及 `str_replace_editor` 的创建、替换、插入操作；读取前后原始字节并核对工具结果 | `src/file-versions.js` |
| 准备历史记录 | Replay turn 确定被替换范围后，仅收集对应有效工具结果涉及的文件；连续写入合并为最初内容与最终内容 | `src/file-versions.js` |
| 保存内容 | Git 工作区使用插件私有 Git blob；其他目录使用 SHA-256 内容对象。两种读取均核验内容地址 | `src/file-snapshots.js` |
| 展示预览 | 读取指定点的记录与持久进度，对当前文件逐字节比较，返回可还原文件和具名拒绝原因；预览不修改工作文件 | `src/file-rollback.js` |
| 确认执行 | 必须提交原预览的 `planId`；先核验整份计划，再逐文件检查；先保存写入意图，后执行，最后保存进度 | `src/file-rollback.js` |
| 恢复文件 | 拒绝越界、`.git`、符号链接、junction、硬链接及非普通文件；写入同目录临时文件并刷盘，再核验目标与 agent 状态后替换；创建文件恢复为不存在 | `src/rollback-files.js` |
| 保存结果 | 完成结果持久保存；最终结果保存中断时，可从最后的完整进度恢复完成状态。已还原或结果不确定的文件不会自动再次写入 | `src/file-rollback.js` |
| 清理与协作 | 会话操作锁协调不同 Host plugin；按会话清理递增 generation，撤销旧预览和缓存；共享内容继续受其他记录保护 | `src/private-storage.js`、`src/storage-cleanup.js` |

观察数据在 Replay turn 前保存在内存。插件重启前未形成的历史记录不会被猜测补全。Shell、任意脚本及未列出的工具写入不在自动捕获范围内。

## 审查发现与处理

严重度按潜在后果排序，不代表发生概率。标注为「代码分析」的原问题没有声称在旧版完成故障复现。

| 严重度 | 原问题与触发条件 | 处理与证据 |
|---|---|---|
| 高 | 工作文件是目录外文件的硬链接时，旧实现允许恢复，连带修改外部别名。独立临时目录已复现 | 读取与恢复均拒绝 `nlink !== 1`；预览前和确认前新增硬链接的两项测试通过，外部内容保持不变 |
| 高 | 直接覆盖写入可能在磁盘写入失败时截断目标。原风险来自代码分析 | 改为同目录暂存、刷盘、重新核验后替换；注入「写出部分暂存字节后失败」，确认目标字节完整、普通失败后暂存文件删除，重试可恢复中文与 CRLF |
| 高 | 原实现仅在最终恢复后保存完成结果。若保存失败并随后重启，内存中的防重复信息丢失。原风险来自代码分析 | 每个文件写入前保存意图、成功后保存进度；验证最终保存失败后直接重启不会再次恢复；进度保存失败时停止后续写入 |
| 高 | Git 读取未核验内容地址；将对象替换为另一段有效压缩 blob，可返回错误原始内容。独立临时目录已复现 | 按 Git blob 格式重新计算 SHA-1 或 SHA-256；实际损坏对象的预览返回 `snapshot-unavailable`，当前文件保持不变 |
| 中 | 同一个 Windows 文件以 `File.txt`、`file.txt` 连续写入，记录没有正确合并。已复现 | Windows 分组使用大小写归一键，展示保留首次路径；测试确认只有一条记录并恢复最初版本 |
| 中 | 写入后缺少核验，外部程序紧接着改动目标时仍返回成功并标记完成。已复现 | 替换后核验；失败记录为不确定结果，阻止自动再次写入；验证当前外部内容保留，重启后不误报完成 |
| 中 | 部分恢复失败后，已恢复文件再次匹配旧后置内容时可能被重做。原风险来自代码分析 | 持久进度识别已还原文件；重试清单显示 `already-restored`，仅处理尚未尝试且核验通过的文件 |
| 中 | 锁目录创建成功但 owner 写入前退出，会留下无 owner 的锁；原实现反复等待后失败。已复现 | 改为完整 owner 文件的原子独占发布；正常死进程锁继续可回收；无法确认归属的旧锁快速明确拒绝，保留现场 |

在新增持久进度机制的审查中，还发现并修复了**跨 Host 读取旧进度**的问题：一个窗口先读取失败进度，另一个窗口恢复完成后，前者必须重新读取磁盘结果。新增两 Host 用例确认完成状态可见，当前文件再次匹配旧内容也不会重复恢复。此项属于本次改进的回归检查，不归为旧实现缺陷。

## 仍存在的限制

1. **最终替换的短暂竞争窗口。** 内容核验和 `rename`／`unlink` 之间仍有操作系统调度间隙。外部程序不参与插件锁，事后核验只能发现部分竞争，无法保证被替换的外部内容可恢复。需要更强保证时，应在执行期间停止外部写入，或另行采用具备原子条件写入能力的宿主机制。
2. **多文件不是事务。** 后面的文件失败时，已恢复文件保留已发生的变化；结果按文件列出。重试保留已还原和不确定文件，仅重新检查未处理文件。
3. **硬终止与断电未做完整耐久性证明。** 测试采用可控故障和插件重启，未模拟整机断电。虽然文件和进度先刷盘再替换，目录项及底层设备的持久性仍依赖操作系统与文件系统。
4. **硬终止可能留下工作目录暂存文件。** `.dsh-resend-*.pending` 在普通失败时清理，强制结束进程时可能保留。私有数据清理不扫描工作目录，避免自动删除用户文件。
5. **未知旧锁和恢复过程中的死亡锁需要人工排查。** 正常带 owner 的主锁在进程死亡后可回收；无法确认 owner 的旧目录锁，以及死亡进程留下的恢复锁，明确返回 `storage-recovery-required`。不能仅按等待时长删除，以免破坏活跃进程。
6. **保存的是内容，不是完整文件元数据。** 已有文件的基本权限随暂存替换保留；时间、文件身份、所有者及平台 ACL 不属于完整还原承诺。Windows 在当前机器上验证，其他文件系统和平台未做同等实机验证。
7. **观察与存储规模尚无压测结论。** 工具写入观察和预览字节保存在内存，没有大文件上限或预览自动过期策略；大文件、大量历史记录及异常断开后的长期内存占用仍需后续专项测试。

完成条件已满足：流程梳理与报告完成；发现的可控缺陷已修复；针对性故障测试、完整测试、构建及宿主隔离验证均通过。上述限制是功能承诺的边界，不作为已验证能力。
