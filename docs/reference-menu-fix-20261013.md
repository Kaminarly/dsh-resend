# 临时输入框查询与菜单修复

日期：2026-10-13（Asia/Hong_Kong）。

## 问题与原因

临时输入框输入 `@` 或 `/` 后，文件与 skill 菜单均显示查询失败。原有浏览器验收直接传入模拟查询对象，没有覆盖注册后的 Client 访问宿主服务这一层。

新增 `test/reference-menu-registration.test.mjs`，通过实际 Cordis 注册作用域渲染插件已构建的用户消息界面。修复前，两项测试分别显示「文件查询失败」和「技能查询失败」，查询方法均未收到请求。

根因是界面所在作用域只声明了 `remote.resend`，未声明 `remote.fileReferences` 与 `remote.skills`。直接读取这两个宿主服务会被 Cordis 的注入检查拒绝。查询参数和结果格式与已安装宿主一致。

## 修复后的行为

- 两个查询服务分别在声明了对应依赖的子作用域内取得，并在作用域结束时撤回；任一查询服务缺失不阻止编辑界面启动或普通文字编辑。
- 文件和 skill 菜单悬浮在蓝色输入边框上方，左右与蓝色边框对齐，向上展开；高度受可用空间限制。
- 菜单复用宿主的 `MenuSurface`、文件图标与 skill 模糊排序，保持相同的背景、阴影、圆角、行高和选中效果。目录支持 Tab 下钻、目录导航和返回上级；Shift+Tab、Escape 或点击框外关闭菜单。
- 查询有匹配候选时，正在输入的 skill 缩写不显示为失效技能；历史失效技能的提示继续保留。
- 移除「在正式输入框中编辑」按钮及停用入口。原有中文提示、独立草稿、撤销、发送和取消继续保留。

## 验证方法与边界

`npm test` 覆盖注册后的查询访问、编辑范围、草稿保留、消息发送和失败恢复。`npm run acceptance:bundle` 重建、检查宿主契约、打包、解包逐文件比较，使用隔离 Profile 加载安装包，并在 Edge 中验证解包后的 Client。

最终完整回归：121 个测试文件通过，1 个按原有条件跳过；2,234 项测试通过，10 项按原有条件跳过。输出见 `output/menu-full-tests.log`。安装包核对、隔离宿主启动和浏览器验收全部通过，输出见 `output/menu-bundle.log`；`output/rich-input-release/latest.json` 指向本轮交付包及完整证据。

浏览器包含 37 组检查，覆盖浅色、深色、1100 px、360 px、目录下钻、鼠标高亮、键盘选择、技能模糊查询和错误状态。样式对照直接渲染本机已安装 DSH Desktop 的 `MenuView`，比较菜单背景、阴影、圆角和候选行的计算样式；同时检查浮层下沿位于蓝色边框上方 4 px，左右与边框对齐。页面异常及控制台错误为 0。

查询的访问作用域使用真实 Cordis 验证，候选 RPC 和发送接收方使用隔离数据。验收没有安装到真实 Profile，没有修改真实用户会话，也没有发起模型请求。

## 后续防护

查询测试应从插件注册后的界面入口触发，避免直接向组件传入模拟服务而绕过宿主访问检查。每次交付继续检查新增宿主控件导出，并对安装包中的实际 Client 运行浏览器验收。
