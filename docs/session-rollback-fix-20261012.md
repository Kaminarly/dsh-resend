# 编辑重发与文件回滚修复记录

日期：2026-10-12（Asia/Hong_Kong）。依据[分析报告](session-rollback-analysis-20261012.md)及用户「实施修复」指令，修复源码并更新 `lib/` 构建产物。

## 修复结果

文件清单已使用宿主真实结果的 `message.toolCallId`、`message.source.callId` 关联修改调用，兼容历史字段和明确的事件引用。以结果在当前回退范围中的归属核验修改，保留子工具修改的处理。绝对和相对路径先归一化，避免同一文件被拆成多项。

结果缺失时，撤回范围内用户消息所属的修改仍进入面板；冲突或重复结果不任意选取。原始快照缺失时说明无法可靠还原。不能读取修改参数或文件路径时停止重发。只有已核验没有变化或首尾内容相同，才跳过确认。

正式输入框的公开 `inputActions` 不能在引用序列化后、普通消息入队前接入重发。本机宿主 `SessionInputShell.sinkSerialized` 直接调用内部 `defaultSink`，`SessionInputHub.sink` 直接调用普通 `sendSession`；临时 Composer 接管也未提供这个发送接入口。因此本轮停用「在正式输入框中编辑」，展示原因，保留临时输入框。即使旧设置关闭临时输入框，仍提供可用的编辑按钮；普通草稿不被覆盖。回车和发送按钮继续共用原有编辑重发及文件确认流程。

完整的正式输入框编辑重发仍未实现，须先由宿主提供受支持的发送接入口。规格已补充原消息目标、普通草稿恢复、失败保留、重复发送、刷新、会话切换、引用序列化及斜杠命令的后续要求。
